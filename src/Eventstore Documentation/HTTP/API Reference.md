# EventStoreDB 22.10 — HTTP API Reference

Base URL used in this documentation: `https://eventstore.com`
(Replace with the actual URL/host and port where your EventStoreDB node or Admin UI is accessible.)

---

## Authentication

HTTP Authentication, scheme: Basic (username/password).

Some endpoints (especially under Admin, Info, certain user management, and `$all` stream access) require valid credentials (e.g. the default `admin:changeit`, unless changed).

## Streams

Endpoints for stream operations.

### Read a stream

```
GET /streams/{stream}
```

Reads a stream, returning a standard AtomFeed document.

Code sample:
```bash
curl -X GET https://eventstore.com/streams/{stream}
```

Parameters:
| Name   | In   | Type   | Required | Description        |
|--------|------|--------|----------|--------------------|
| stream | path | string | true     | The stream ID      |
| embed  | query| string | false    | See embed enum     |

Enumerated values for `embed`:
- None
- Content
- Rich
- Body
- PrettyBody
- TryHarder

Responses:
| Status | Meaning     | Description | Schema |
|--------|-------------|-------------|--------|
| 200    | OK          | OK          | None   |
| 404    | Not Found   | Not found   | None   |

Authentication: Not required for ordinary streams; required for restricted streams.

---

### Append to a stream

```
POST /streams/{stream}
```

Append events to a stream. If the stream does not exist, it is created implicitly.

Code sample:
```bash
curl -X POST https://eventstore.com/streams/{stream} \
  -H 'Content-Type: application/json' \
  -H 'ES-ExpectedVersion: 0' \
  -H 'ES-EventType: string' \
  -H 'ES-EventId: 00000000-0000-0000-0000-000000000000' \
  -H 'ES-RequiresMaster: true' \
  -d '{"body": {}}'
```

Body parameter (example schema):
```json
{
  "body": {}
}
```

Parameters:
| Name             | In     | Type    | Required | Description                                |
|------------------|--------|---------|----------|--------------------------------------------|
| stream           | path   | string  | true     | The name of the stream                     |
| ES-ExpectedVersion | header | integer | false  | Expected stream version                    |
| ES-EventType     | header | string  | false    | The event type associated to posted body   |
| ES-EventId       | header | integer | false    | Event ID (UUID) associated to posted body  |
| ES-RequiresMaster| header | boolean | false    | Whether to run on master node              |
| body             | body   | streamData | true  | Stream events to create                    |

Responses:
| Status | Meaning            | Description                | Schema |
|--------|--------------------|----------------------------|--------|
| 201    | Created            | New stream created         | None   |
| 307    | Temporary Redirect | Idempotent redirect URL    | None   |
| 400    | Bad Request        | Append request body invalid| None   |

Authentication: Not required for ordinary streams (unless ACLs demand it).

### Delete a stream

```
DELETE /streams/{stream}
```

Delete a specified stream (soft delete by default).

Code sample:
```bash
curl -X DELETE https://eventstore.com/streams/{stream}
```

Parameters:
| Name   | In   | Type   | Required | Description           |
|--------|------|--------|----------|-----------------------|
| stream | path | string | true     | The stream ID to delete|

Responses:
| Status | Meaning     | Description      | Schema |
|--------|-------------|------------------|--------|
| 204    | No Content  | Stream deleted   | None   |

Authentication: Not required (unless ACLs require).

For hard delete add header: `ES-HardDelete:true` (will result in tombstone; subsequent GET returns 410).

## Notes

- Use `ES-ExpectedVersion` for optimistic concurrency; special values: -2 (always succeed), -1 (stream must not exist), 0 (stream must exist and be empty), -4 (stream or metadata stream must exist).
- Use `embed` parameter to control event embedding style.
- Use `ES-LongPoll` header to reduce latency in hot feeds.
- Persistent subscriptions to `$all` not available over HTTP.
- Hard deletes are irreversible (tombstone).
- Use Basic auth over HTTPS to protect credentials.
- For idempotent appends, include `ES-EventId` or use the event batch media type.
